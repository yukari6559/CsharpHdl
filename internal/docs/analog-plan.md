# SharpHDL アナログ・混在信号モード計画（SX13）

アナログ回路と、アナログとデジタルが混ざった回路（混在信号、mixed-signal）を C# で書き、FPGA とは別のモードで、外部のシミュレータと C# の Sim の両方で検証できるようにする計画。
起点は Verilog-AMS だが、一つの言語をそのまま写さず、複数の言語の良いところを取り入れる。

- 状態: **計画（未着手）**。実装は人手で行う
- 課題: YouTrack [SHDL-188](https://araiguma.youtrack.cloud/issue/SHDL-188)（SX13 の親）、[SHDL-189](https://araiguma.youtrack.cloud/issue/SHDL-189)（この文書）
- 関連: [hdl-coverage-plan.md](hdl-coverage-plan.md) §4.4（SX13 の一覧の行）、[sim-spec.md](sim-spec.md)（今の Sim）、[long-term-plan.md](long-term-plan.md)

---

## 0. 位置づけ

[hdl-coverage-plan.md](hdl-coverage-plan.md) の HC0–HC9 は「Verilog / SystemVerilog の全機能を書けるようにする」計画で、対象は合成できるデジタル回路である。アナログ回路は FPGA では作れない（LUT とフリップフロップは 0/1 しか扱えない）ので、HC の外に置き、SharpHDL 独自機能 **SX13** とする。

ターゲット種別（`fpga` / `asic`、hdl-coverage-plan §4.3）と同じ切り替えの仕組みで、アナログを扱うモードを足す。FPGA モードの検査・出力・一括実行の流れは変えない。

## 1. 前提の用語

この文書で初めて出る語を先にまとめる。

| 語 | 意味 |
|----|------|
| **アナログ回路** | 電圧と電流が連続した値をとり、時間とともに連続に変わる回路。デジタル回路の「0/1」と「クロックの拍」とは扱いが違う |
| **節点（node）** | 配線がつながった一点。電圧はこの点ごとに決まる。基準の節点を **グラウンド**（0 V）とする |
| **枝（branch）** | 2 つの節点の間にある素子（抵抗、コンデンサなど）。電流は枝を流れる |
| **ポテンシャルとフロー**（across / through） | 2 種類の量の分け方。**ポテンシャル** は 2 点の間の差で測る量で、電気では電圧（単位 V、正の向きは「+ 側の節点のほうが高い」）。**フロー** は枝を通って流れる量で、電気では電流（単位 A、正の向きは「+ 端子から入って − 端子へ抜ける」）。機械（速度と力）や熱（温度と熱流）も同じ対で書ける |
| **キルヒホッフの電流則** | 節点に流れ込む電流の合計は 0。回路の方程式はこの則と素子の式から立つ |
| **nature / discipline**（Verilog-AMS の語） | nature は量の種類（単位と、どこまでの誤差を許すか）。discipline はポテンシャルの nature とフローの nature の組。電気の discipline `electrical` は「電圧」と「電流」の組 |
| **解析の種類**（SPICE の語） | `.op`（動作点：直流で落ち着いた後の値）、`.dc`（電源の値を振って `.op` を繰り返す）、`.tran`（過渡解析：時間を進めて波形を出す）、`.ac`（小さな正弦波を入れたときの周波数ごとの利得と位相）。SPICE はアナログ回路シミュレータの元祖で、今の多くのシミュレータがこの語を使う |
| **時間刻み（timestep）** | 過渡解析で時間を進める幅。多くのシミュレータは、波形が急に変わるところで刻みを自動で細かくする |
| **許容誤差（reltol / abstol）** | アナログの結果は厳密な値ではなく、誤差の範囲で正しい。reltol は値に対する割合、abstol は値が 0 に近いときの絶対量。SPICE の既定は reltol = 1e-3、電圧の abstol = 1e-6 V、電流の abstol = 1e-12 A |
| **MNA（修正節点解析）** | 節点の電圧と、電圧源などの枝の電流を未知数にして、連立一次方程式 \(A x = b\) を立てる方法。SPICE の中心にある |
| **DAE（微分代数方程式）** | 微分を含む式（コンデンサの \(i = C\,dv/dt\)）と含まない式（抵抗の \(v = R\,i\)）を連立したもの。アナログ回路の方程式は一般にこの形になる |
| **陰的積分**（後退オイラー、台形則） | \(dv/dt\) を「次の時刻の値」を使って近似し、連立方程式として解く方法。刻みを大きくしても値が発散しにくいので回路シミュレータの標準。後退オイラーは 1 次、台形則は 2 次の精度 |
| **ニュートン・ラフソン法** | ダイオードやトランジスタのような非線形の素子を、線形の近似を繰り返して解く方法。初期値によっては収束しない |
| **RNM（Real Number Modeling）** | アナログ値を実数として、デジタルと同じイベント駆動（値が変わったときだけ計算する）で扱う手法。回路方程式は解かないので速いが、つないだ相手によって電圧が変わる効果（負荷効果）は表せない |
| **A/D 境界** | 連続値と 0/1 の境目。アナログからデジタルへはしきい値（何 V 以上を 1 とするか）とヒステリシス（行きと帰りでしきい値をずらし、境目でのばたつきを防ぐ幅）、デジタルからアナログへは出力電圧と立ち上がり時間で決まる |

## 2. 各言語から取り入れるもの

| 言語 | どういうものか | 取り入れる | 取り入れない |
|------|----------------|------------|--------------|
| **Verilog-AMS / Verilog-A**（Accellera、LRM 2.4） | Verilog にアナログ記述を足した言語。Verilog-A はそのアナログ部分だけ。素子は「寄与文」`I(p, n) <+ V(p, n) / R;`（この枝の電流にこの量を足す）で書く | discipline / nature による量の区別、寄与文の考え方、アナログ演算子（`ddt` 微分、`idt` 積分、`transition` 段差をなめらかにする、`cross` / `above` しきい値を横切った瞬間を検出、`timer` 時刻指定のイベント、`absdelay` 遅延、`laplace_*` 伝達関数）。**出力先として最重要**（§6） | **connect module の自動挿入**（アナログとデジタルの境目に変換器を暗黙に入れる仕組み）。暗黙のクロック（dsl-spec §6）や暗黙の符号拡張（long-term-plan「意図的に後回し」）を禁じたのと同じ理由で、境界は明示する |
| **VHDL-AMS**（IEEE 1076.1） | VHDL にアナログ記述を足した言語。`quantity`（連続量）、`terminal`（端子）、同時文 `==`（左右が等しいという方程式） | 量に型を付けて取り違えをコンパイルで止める考え方、多分野（機械・熱）を同じ枠で書ける点、`break`（不連続な変化をシミュレータに知らせて刻みを切り直させる）の明示 | 出力先としては後回し。オープンソースのシミュレータがほとんど無い |
| **SystemC AMS**（IEEE 1666.1） | C++ のライブラリとして提供される AMS 拡張。抽象度の違う 3 つの計算モデルを持つ：**TDF**（時間刻み固定のデータフロー。信号処理向けで速い）、**LSF**（線形のブロック図）、**ELN**（線形の電気回路網） | 「抽象度の段を選べる」分け方を、自作 Sim の段階分け（§5）にそのまま使う。ライブラリとして言語に乗る立ち位置は、C# のライブラリである SharpHDL と同じ | SystemC への依存。参照実装（COSEDA の Proof-of-Concept、Apache 2.0）は設計の参考にとどめる |
| **SPICE**（ngspice、Xyce、SpiceSharp など） | 素子のつながり（ネットリスト）を書き、MNA で解くシミュレータ群。トランジスタの精密なモデル（BSIM など）を持つ | 解析の種類（`.op` / `.dc` / `.tran` / `.ac`）の語彙、ネットリストの出力、トランジスタレベルの検証先、ngspice のデジタル部分との同時実行（`d_cosim`） | カード形式の文法そのものを DSL にしない |
| **Modelica** | 物理系全般を方程式で書く言語。**connector**（ポテンシャル変数とフロー変数を持つ接続口）をつなぐと、キルヒホッフの則に当たる式を自動で立てる。部品ライブラリ（Modelica Standard Library）が厚い | connector の考え方（つなぐだけで保存則が立つ）、部品ライブラリの組み方、**FMI**（Functional Mock-up Interface：シミュレーション部品を FMU というファイルにして別のツールと交換・連携する標準）による外部ツールとの連携 | 記号的な式変形（Modelica コンパイラが行う、方程式を解きやすい形に並べ替える処理）を自作しない |
| **SystemVerilog の RNM**（`real` 変数、IEEE 1800-2012 の `nettype`） | デジタルのシミュレータの上で、アナログ値を実数として流す業界の常套手段 | **最初の段（SX13b）として採る**。いちばん安く、今の Sim（イベント駆動・拍単位）の延長で作れる。出力は SV の `real` / Verilog-AMS の `wreal` | `nettype` の解決関数（複数の駆動元を合成する関数）は、Verilator・Icarus の対応を確かめてから決める |

## 3. 原則

1. **抽象度の段を選べる。** 同じ部品（例：ローパスフィルタ）に、RNM の振る舞い、固定刻みのデータフロー、線形回路網、トランジスタのネットリスト、の複数の段を持たせられる。検証の目的（速さか精度か）で段を選ぶ。段の間の答え合わせ自体が検証になる
2. **量は型で区別する。** 電圧と電流、抵抗と容量を別の型にし、電圧と電流を足すとコンパイルエラーにする。単位の付いた量は SX4（型による安全性、固定小数点）と同じ考え方
3. **A/D 境界は明示する。** Verilog-AMS の connect module のような自動挿入はしない。境界は部品として置き、しきい値、ヒステリシス、遅延、出力電圧を引数で必ず渡す
4. **比較は許容誤差つき。** デジタルはビット一致で比べるが、アナログは §6.2 の規則で比べる。境界を越えたあとのデジタル値はビット一致で比べ、変化した時刻だけ許容幅を持たせる
5. **時間は明示する。** 今の Sim の `Advance` は「拍」で進み、秒を持たない（[sim-spec.md](sim-spec.md) §4）。アナログは秒で進む。混在させるときは、クロックの周期を秒で宣言して拍と秒を対応させる。暗黙の周期は持たない
6. **FPGA モードの出力を変えない。** アナログの原語を足しても、`fpga` モードで出る Verilog の文字列は変わらない

## 4. モード

### 4.1 ターゲット種別との関係

| 項目 | `fpga`（今） | `asic`（SX12） | アナログ・混在信号モード（SX13） |
|------|--------------|----------------|-----------------------------------|
| 書けるもの | デジタル（合成できる範囲） | デジタル（ASIC 向けの検査つき） | デジタル + アナログ部品 + 明示した A/D 境界 |
| Sim | 2 値、拍で進む | 4 値（オプション） | 2 値のデジタル + 実数のアナログ、秒で進む |
| 出力 | Verilog-2001、制約（`.cst` など） | Verilog / SV、SDC | デジタルは Verilog のまま。アナログは Verilog-AMS / Verilog-A、SPICE ネットリスト、SV の `real` |
| 一括実行の段階 | Sim → RTL シミュ → 一致確認 → 合成 → 書き込み | … → GDS | Sim → 外部アナログ / 混在シミュ → 許容誤差つき一致確認。合成と書き込みは無い |
| アナログ部品の扱い | 合成対象にしない（下の 4.2） | 混在信号チップは SX13g で合流 | 本体 |

モードの値の名前（`sharphdl.json` に書く文字列）の候補：

| 候補 | 理由 |
|------|------|
| `ams`（おすすめ） | Verilog-AMS / VHDL-AMS / SystemC AMS と同じ語で、調べるときに迷わない。`fpga` / `asic` と同じく短い |
| `mixed-signal` | 意味がいちばん直接に伝わる。ただし他の値より長く、ハイフンを含む |
| `analog` | 短いが、デジタルも同時に書けることが伝わらない |

### 4.2 要決定：FPGA モードでのアナログ部品

FPGA の基板にも、PWM やΔΣ（デルタシグマ：1 ビットの速いパルス列の密度で値を表す方式）の出力を抵抗とコンデンサでならして音にする、といったアナログ部分が付く。そこで次の 2 案がある。

| 案 | 内容 |
|----|------|
| A（おすすめ） | `fpga` モードでも、アナログ部品を **テスト側の環境モデル** としてだけ使える。Emit の対象（合成に渡す Verilog）には入れず、入れようとしたら検査でエラーにする |
| B | `fpga` モードではアナログ部品を一切使えない。基板のアナログ部分を確かめたいときは `ams` モードに切り替える |

### 4.3 要決定：ASIC と組み合わせるとき

混在信号チップ（アナログ回路を載せた ASIC）では `asic` と `ams` の両方が要る。ターゲット種別に第 3 の値として足すか、「アナログ有効」をターゲット種別とは別の軸にするかを SX13a で決める。

## 5. 段階

SystemC AMS の計算モデルの分け方にならい、安くて速い段から精密な段へ進める。各段で「C# Sim」と「外部のシミュレータ」の両方で検証できるようにする。

| ID | 内容 | 出力 / 外部の検証先 | 前提 |
|----|------|----------------------|------|
| **SX13a 量の型と境界** | 単位つきの量（電圧、電流、抵抗、容量、インダクタンス、周波数、時間）、節点と端子、明示の A/D・D/A 境界部品、モードの切り替えと検査。Emit と Sim はまだ無い | なし（型と検査のテスト） | SX4 |
| **SX13b 実数信号（RNM）** | 実数の信号をイベント駆動で流す。Sim に「秒」と時刻つきイベントを足し、クロックの周期で拍と秒を対応させる | SV の `real`（Icarus / Verilator）、Verilog-AMS の `wreal` | SX13a、HC8 の VCD |
| **SX13c 固定刻みデータフロー**（TDF 相当） | 決まった刻みで値を流すブロック（フィルタ、変調器、ADC・DAC の振る舞いモデル） | Verilog-A / Verilog-AMS の振る舞い記述 | SX13b |
| **SX13d 線形回路網**（ELN 相当） | 抵抗、コンデンサ、インダクタ、電圧源、電流源、制御電源。MNA と陰的積分で `.op` / `.tran` / `.ac` を解く | SPICE ネットリスト（ngspice、Xyce）、SpiceSharp | SX13a |
| **SX13e 振る舞い記述の原語** | Verilog-A の寄与文とアナログ演算子（`ddt` / `idt` / `cross` / `transition` / `timer`）に当たる C# の原語 | Verilog-A（ngspice + OpenVAF、Xyce + ADMS、Gnucap）、Verilog-AMS（商用の AMS シミュレータ） | SX13c、SX13d |
| **SX13f 混在シミュレーション** | 今の Module（デジタル）とアナログ部分を同時に動かす。自作 Sim では拍と秒を同期する。外部では ngspice の `d_cosim` で Verilator / Icarus の出力を回路の中に置く | ngspice + `d_cosim`、商用の AMS シミュレータ | SX13b、SX13d、SX2 の一括実行 |
| **SX13g 非線形素子と外部モデル**（長期） | ダイオード、MOSFET、PDK（半導体工場が配る素子モデル一式）のモデル。自作 Sim のニュートン法は小さな回路の答え合わせ用にとどめ、本格的な検証は外部に任せる | ngspice + PDK（SKY130 など）。SX12c と合流して混在信号チップへ | SX13d、SX12c |
| **SX13h FMI 連携**（長期） | C# の回路を FMU にして、または FMU を取り込んで、機械・熱のモデルと連成する（モーター制御など） | OpenModelica などの FMI 対応ツール | SX13c |

### 5.1 新しいプロジェクトの名前（SX13a で決める）

単位つきの量と境界部品を Core に入れるか、別のプロジェクトに分けるかは要決定。分ける場合、フォルダ名・csproj 名・ルート名前空間を同じにする。

| 候補 | 理由 |
|------|------|
| `SharpHdl.Analog`（おすすめ） | 何が入っているかが一語で伝わる。`SharpHdl.Sim` / `SharpHdl.Emit` と同じく一語 |
| `SharpHdl.Ams` | モードの値を `ams` にするなら揃う。略号なので初見では伝わりにくい |
| `SharpHdl.MixedSignal` | 混在信号まで含むことが伝わる。長い |

### 6.2 比較の規則

- 2 つの波形の時刻を揃え（刻みが違うので、片方を線形補間する）、各時刻で \(|a - b| \le \text{abstol} + \text{reltol} \times \max(|a|, |b|)\) を満たせば一致とする。\(a\)、\(b\) は比べる 2 つの値、abstol と reltol は §1 の許容誤差
- 既定は SPICE と同じ：reltol = 1e-3、電圧の abstol = 1e-6 V、電流の abstol = 1e-12 A。量の型ごとに既定を持ち、テストで上書きできる
- A/D 境界を越えた後のデジタル値はビット一致。変化した時刻は許容幅（既定は要決定）の中なら一致
- 比較の結果は SX2 の一致確認（hdl-coverage-plan §4.1）と同じ形でログに出す

### 6.3 ゴールデン

**RC 回路のステップ応答**：R = 1 kΩ、C = 1 µF を直列にし、時刻 0 で入力を 0 V から 1 V にする。時定数 \(\tau = RC = 1\) ms。コンデンサの電圧は \(V(t) = 1 - e^{-t/\tau}\) [V]。

| 時刻 | 厳密値 |
|------|--------|
| 0.5 ms | 0.3935 V |
| 1 ms | 0.6321 V |
| 2 ms | 0.8647 V |
| 5 ms | 0.9933 V |

**積分方法で値が変わる例**（刻み h = 0.1 ms の固定刻みで 1 ms まで進めた値）。許容誤差が要る理由であり、自作 Sim の積分方法を確かめる数でもある。

| 積分方法 | V(1 ms) | 厳密値 0.6321 V との差 |
|----------|---------|------------------------|
| 後退オイラー | 0.6145 V | −0.0177 V |
| 台形則 | 0.6324 V | +0.0003 V |

**同じ RC の周波数応答（`.ac`）**：遮断周波数 \(f_c = 1/(2\pi RC) = 159.15\) Hz で利得 \(1/\sqrt{2} = 0.7071\)（−3.01 dB）。

**動作点（`.op`）**：5 V を R1 = 1 kΩ と R2 = 2 kΩ で分圧すると、R2 の両端は 3.333 V。

**RNM（SX13b）**：3.3 V・デューティ 25 % の PWM を理想の平均化フィルタに通すと 0.825 V。

## 7. 既存の計画との関係

| 既存 | 関係 |
|------|------|
| SX4 型による安全性 | 単位つきの量は同じ考え方。固定小数点（Q 形式）の値をアナログの実数へ渡す境界部品で使う |
| HC8 / SX5 検証、VCD | VCD は実数の値も記録できる（変数の種類 `real`）。アナログ波形も同じ VCD に出し、VS Code で並べる |
| SX2 一括実行 | 段階に「外部アナログシミュ」「許容誤差つき一致確認」を足す。役割ごとのバックエンドの仕組みに ngspice などを載せる |
| SX6 部品ライブラリ | PWM DAC、ΔΣ DAC、RC フィルタ、比較器（コンパレータ）を、デジタル側とアナログ側の対で配る |
| SX9 複数の出力言語 | Verilog-A / Verilog-AMS / SPICE ネットリストは、その仲間として出力の仕組みを共有する |
| SX12 ASIC | 混在信号チップは SX12c（オープンソース ASIC フロー）と SX13g が合流する先。Tiny Tapeout などのアナログ端子付きの枠も候補（提供状況は要確認） |
| [sim-spec.md](sim-spec.md) | 今の Sim は秒を持たない。SX13b で時刻の扱いを sim-spec に足す。`fpga` モードの `Settle` / `Advance` の意味は変えない |

## 8. やらないこと

| やらない | 理由 |
|----------|------|
| アナログ回路の自動合成・自動レイアウト | 研究段階の分野で、範囲が大きすぎる |
| 記号的な式変形（Modelica コンパイラ相当） | 自作の負担が大きい。必要な連成は FMI で外部に任せる |
| SPICE の全素子モデルの自作 | 非線形の精密なモデルは外部（ngspice + PDK）に任せる。自作 Sim は線形回路網と小さな非線形の答え合わせまで |
| A/D 境界の自動挿入 | 暗黙の変換はバグの元（§3 の 3） |

## 9. 位置づけ（Stage）

- SX13a は SX4（Stage 3）の型の仕組みができてから。SX13b 以降は HC8（Stage 4）の VCD と検証の仕組みの後
- Stage 6（ASIC）とは独立に進められる。SX13g だけが SX12c を待つ
- 案：hdl-coverage-plan に **Stage 7 — アナログ・混在信号** を足し、SX13a〜SX13f を本体、SX13g / SX13h を長期とする（要決定）
