# HDL 機能カバレッジ計画（Verilog / SystemVerilog 10 割 + SharpHDL 独自）

SharpHDL の DSL が **Verilog-2005（IEEE 1364）と SystemVerilog-2017（IEEE 1800）の機能をどこまで扱えるか** を全項目で棚卸しし、
**全項目を「対応済み」にする計画**と、**C# で書く HDL だからできること**の計画をまとめる。

- 既存の本線（[ROADMAP.md](ROADMAP.md)、[tickets/midisynth-tang-primer25k-requests.md](tickets/midisynth-tang-primer25k-requests.md) の M2–M7）と、
  長期計画（[long-term-plan.md](long-term-plan.md) の L1–L4 / Phase B–H）は **このドキュメントの段階（Stage）に組み込む**。番号は既存のものをそのまま使う
- 仕様の正本は従来どおり [dsl-spec.md](dsl-spec.md) / [verilog-emit-spec.md](verilog-emit-spec.md) / [sim-spec.md](sim-spec.md)。ここは **何を・どの順で** の正本

## 1. 「10 割対応」の定義

HDL の機能には、合成できない（シミュレーション専用）ものや、C# で書く以上ネイティブに持つ意味がないものが含まれる。
そこで各機能に **方針** を 1 つ割り当て、**全行が方針どおりに完了した状態を 10 割** とする。

| 方針 | 意味 | 「完了」の条件 |
|------|------|----------------|
| **ネイティブ** | DSL の原語として持ち、Emit と Sim が同じ意味論で扱う | Core + Emit + Sim + テスト + dsl-spec 記載 |
| **C# 代替** | C# の言語機能（メソッド、ループ、`const`、名前空間、ジェネリクス）で同じことが書ける | dsl-spec に「この Verilog 機能は C# でこう書く」を例付きで記載。必要なら補助 API |
| **Sim 代替** | シミュレーション専用の機能。Verilog には出さず、C# の Sim / テストで同じことをする | Sim API + sim-spec 記載 + テスト |
| **除外** | 合成できない・バグの元・HDL の範囲外のため、意図的に持たない | dsl-spec §6 に理由付きで記載し、使えないことを明示 |

状態の記号: ✅ 完了 / 🟡 一部 / ❌ 未着手。

**現在の到達度（2026-10-14、M4a まで）:** 全 133 項目のうち ✅ 22、🟡 11 → **約 21%**（🟡 は 0.5 で計算）。
ネイティブ方針の 86 項目に限ると ✅ 22、🟡 9 → **約 31%**。
C# 代替・Sim 代替・除外の 47 項目は、ほぼ「方針は決まっているが文書化されていない」状態。

> 以前の目安「合成できる Verilog-2001 の約 36%」は、よく使う 43 項目だけを数えたもの。本書は SystemVerilog と検証機能まで含めた全量なので分母が大きい。

### 4.1 検証から書き込みまでのワークフロー（SX2 の詳細）

**目的:** C# で書いた回路を、C# Sim → RTL シミュレーション → 一致確認 → 実機書き込みまで 1 操作で通す。各段階は省略できる。

#### 段階と省略の規則

| 段階 | 内容 | 省略 | 前提 |
|------|------|------|------|
| ① describe | `Describe` を 1 回だけ呼び、静的チェック（幅・多重駆動・代入文脈、将来は SX3） | 不可 | — |
| ② sim | C# Sim を実行。波形（VCD）を出力し、毎サイクルの入力ポート値を **入力ファイル** に記録 | 可 | ① |
| ③ emit | Verilog と制約ファイル（`.cst` など）を出力。② を実行した場合は、入力ファイルを再生する **テストベンチも生成** | 不可 | ① |
| ④ rtlSim | 選んだバックエンドで RTL シミュレーション。生成テストベンチで同じ入力を与え、毎サイクルの出力を記録し、VCD も出す | 可 | ②（入力ファイル）、③ |
| ⑤ compare | ② と ④ の記録をサイクルごとに比較。不一致なら「何サイクル目・どの信号・Sim の値・RTL の値」を報告 | 可 | ② と ④ の両方を実行したとき。どちらかを省略したら自動で省略 |
| ⑥ build | 合成 → 配置配線 → ビットストリーム生成 | 可 | ③ |
| ⑦ program | 実機への書き込み（SRAM / Flash を選択） | 可 | ⑥ の成果物。⑥ を省略した場合は前回の成果物を使い、無ければエラー |

- ⑤ で不一致なら **既定で停止**（⑥ ⑦ に進まない）。強制的に進めるオプションを用意する
- 入力に変更がない段階を省略するキャッシュは後から足す（最初は無し）

#### 比較の規則（⑤）

- 比べる時点: 各クロックの立ち上がりの後、組み合わせ回路が落ち着いた値（C# Sim の `Advance` + `Settle` 後に相当）
- 対象: 最初は **トップのポートのみ**。ローカル信号はオプション（M4b #8、#15 の後）
- 初期状態: RTL のリセット前の不定値と C# Sim の 0 が食い違うため、**リセット解除後から比較**。HC2 のレジスタ初期値が入ったら全サイクル比較を選べるようにする
- 比較には値を並べたサイクルごとのテキスト記録を使う（VCD は人が見る用）
- ブラックボックス（PLL など）を含む設計は、C# Sim 用の振る舞いモデルとベンダーのシミュレーションモデルの両方が必要。無い場合はその出力を比較対象から外す

#### バックエンド（段階ごとに選ぶ）

[long-term-plan.md](long-term-plan.md) Phase D の `IBackend` を、**段階ごとの役割**に分けた共通インターフェースにする。1 つのバックエンドが複数の役割を持ってよい。

| 役割 | 担う段階 |
|------|----------|
| RTL シミュレータ | ④ |
| 合成・配置配線・ビットストリーム | ⑥ |
| 書き込み | ⑦ |

方針: **書き込み先 FPGA のベンダーツールを第一候補** とし、ベンダーツールに無い役割・動かない環境はオープンソースで補う。

| バックエンド | RTL シミュレータ | 合成〜ビットストリーム | 書き込み | 備考 |
|--------------|------------------|------------------------|----------|------|
| Gowin EDA（Gowin） | 同梱なし（要確認。ベンダーのシミュレーションモデルは提供） | あり（`gw_sh`） | あり（`programmer_cli`） | **macOS 非対応**（Windows / Linux） |
| Vivado（AMD） | あり（xsim） | あり | あり | macOS 非対応 |
| Quartus Prime（Intel / Altera） | あり（Questa の FPGA 向け版） | あり | あり（`quartus_pgm`） | macOS 非対応 |
| オープンソース一式 | Icarus Verilog / Verilator | yosys + nextpnr-himbaechel + Apicula（Gowin 向け） | openFPGALoader | macOS で動く |

- Tang Primer 25K を Mac で使う場合: ④ は Icarus Verilog か Verilator（Gowin のシミュレーションモデルを読み込む）、⑥ はオープンソース一式、⑦ は openFPGALoader が現実的。Gowin EDA を使う場合は Windows / Linux 機か VM
- バックエンドの実装順: オープンソース一式（Mac で全段階が通る）→ Gowin EDA → Vivado / Quartus

#### 設定（`sharphdl.json` + 実行時引数）

- 各段階の有効・無効、段階ごとのバックエンド、出力先、ボード、比較対象を `sharphdl.json` に書く（CLI / VS Code タスク / 将来の VS Code 拡張が同じ設定を読む）
- 実行時の引数で上書きできる（例: 特定段階の省略、バックエンドの切り替え、不一致時の強制続行）

#### VS Code

- 段階ごとのタスクと、全段階を通すタスク（既定のビルドタスク）を提供
- ツールのエラーと比較の不一致を Problems / 出力パネルに表示
- C# Sim と RTL の VCD を波形ビューア（VS Code 拡張、または GTKWave）で並べて見られる

### 4.2 VS Code からの実機デバッグ（SX11 の詳細）

**目的:** 実機の FPGA の中で信号がどう動いているかを、C# の信号名のまま VS Code で見る。C# Sim・RTL シミュレーションとの 3 者比較もできるようにする。

**方式:** ベンダー製の内蔵ロジックアナライザ（Gowin GAO、Vivado ILA、Quartus SignalTap）は各社の開発ツールが必要で、Gowin EDA は macOS で動かない。そこで **SharpHDL がデバッグ用の回路を自分で挿入する** 方式を本線とし、ベンダー製はバックエンドの選択肢として後から足す。

| 段階 | 内容 |
|------|------|
| SX11a 観測点とデバッグ回路 | C# で観測する信号（プローブ）とトリガ条件（C# の式）を指定。デバッグ用ビルドのときだけ、トリガ判定・記録用メモリ（BRAM のリングバッファ、トリガ前後の深さを指定）・PC との通信回路を自動で挿入。通常ビルドには一切入らない |
| SX11b 記録の吸い上げと VS Code 表示 | PC 側の C# ツールが通信で記録を開始・回収し、C# の信号名のまま VCD に変換。一括実行の段階（`capture`）として追加し、VS Code のタスクで「書き込み → 記録 → 波形表示」を 1 操作に。C# Sim / RTL の VCD と並べて比較 |
| SX11c 実機レジスタの読み書き | 指定した信号の現在値の読み出し、指定したレジスタへの書き込みを PC から行う（ベンダーの Virtual I/O 相当）。VS Code の出力パネルや簡易パネルから操作 |
| SX11d VS Code のデバッガ UI | Debug Adapter Protocol で VS Code のデバッグ画面に統合。「変数」= 観測信号、「ブレークポイント」= トリガ条件（C# の行に紐付け）、「停止」= 記録完了、「ウォッチ」= 実機レジスタ。VS Code 拡張（SX7）の一部 |
| （後）ベンダー製ロジアナ | Gowin GAO などをバックエンドの「デバッグ」役割として選べるようにする（Windows / Linux） |

**通信路:** 最初は Tang Primer 25K の Dock に載っているデバッガの USB-UART を使う（FPGA 側のピン接続は T0 #86 で確認）。JTAG 経由は後から。

**前提:** 一括実行の土台（#89）、オープンソースの build / program（#90）、VCD 出力（#87）、ボード定義（#88）、汎用メモリ（HC2）。UART などの通信回路は部品ライブラリ（SX6）の最初の部品として作る。#15（子モジュール名の安定化）があると階層内の信号を名前で指定しやすい。

**注意:** デバッグ回路は LUT・BRAM を消費し、タイミングにも影響する。挿入した場合の資源使用量を一括実行のログに出す。

### 4.3 半導体（ASIC）設計・検証への発展（SX12 の詳細）

**目的:** FPGA 向けに育てた DSL・Sim・一括実行・検証の仕組みを、**半導体（ASIC）の設計と検証** に広げる。
設計では「C# で書いた回路を GDS（チップのレイアウトデータ）まで通す」、検証では「C# で書いたテスト環境で、SharpHDL 製でない既存の Verilog / SystemVerilog 設計も検証できる」ことを目指す。

#### FPGA との違いで、計画の前提が変わる点

| 項目 | FPGA（Stage 1–5 の前提） | ASIC で必要になること |
|------|--------------------------|------------------------|
| 不定値 X | Sim は 2 値。`===` などは除外 | リセット漏れ・X の伝播を見つけるため、**Sim に 4 値モード（オプション）** が要る。HC6 で値の表現を変えるときに 4 値へ拡張できる設計にしておく |
| レジスタの初期値 | 使える（HC2） | 使えない（電源投入時の値は不定）。ASIC 向けでは **検査でエラー** にし、リセットで初期化させる |
| ゲーテッドクロック | 除外（イネーブルで代替） | 消費電力削減のため **専用のクロックゲーティングセル経由なら許可**（ブラックボックス #93 で扱う） |
| メモリ | BRAM に推論させる | SRAM マクロ（PDK 付属、または OpenRAM などのメモリコンパイラ）を **ブラックボックスで配置** |
| 制約 | ピン配置（`.cst` など） | **SDC**（クロック定義、入出力遅延、例外パス）とタイミング解析が中心 |
| 出力言語 | Verilog-2001 で十分 | 商用 EDA との連携のため **SystemVerilog 出力（HC9）** の重要度が上がる |

これらを `sharphdl.json` の **ターゲット種別（`fpga` / `asic`）** で切り替え、検査・出力・バックエンドの既定値を変える。

#### 段階

| ID | 内容 | 前提 |
|----|------|------|
| SX12a ASIC ターゲット | ターゲット種別の切り替え、ASIC 向け検査（初期値禁止、ゲーテッドクロックの制限、X の発生源の検出）、Sim の 4 値モード | HC6、SX3 |
| SX12b 制約とタイミング | C# から SDC を出力（クロック、入出力遅延、例外パス）。OpenSTA などのタイミング解析を一括実行の段階として呼ぶ | SX1 の仕組み、#89 |
| SX12c オープンソース ASIC フロー | yosys + OpenROAD 系のフロー（OpenLane 系）をバックエンドとして追加。オープンな PDK（SKY130 / GF180MCU / IHP SG13G2 など）で GDS まで。Tiny Tapeout などの共同試作（シャトル）のテンプレート（提供状況は要確認） | #89、SX12b |
| SX12d 合成後の検証 | 合成後のゲートレベルネットリストのシミュレーションを、Sim と RTL の一致確認（#91）に第 3 の比較対象として追加。RTL と合成後ネットリストの等価性検査（yosys の eqy など） | #91、SX12c |
| SX12e 形式検証 | C# で書いたアサーション・性質（HC8）を SymbiYosys などに渡し、有界モデル検査・証明を行う。反例は VCD で VS Code に表示 | HC8、#87 |
| SX12f C# による検証基盤 | UVM 相当（トランザクション、ドライバ・モニタ、スコアボード、制約付き乱数、機能カバレッジ）を C# で。cocotb の C# 版に当たる | HC8、SX5 |
| SX12g 既存 RTL の検証 | SharpHDL 製でない Verilog / SV モジュールをブラックボックスとして取り込み、C# のテスト環境から RTL シミュレータ経由で駆動・検証する。商用シミュレータ（Questa / VCS / Xcelium）とは VPI / DPI 経由で接続 | #93、SX12f |
| SX12h DFT・電力（長期） | スキャン挿入はツール側に任せ、C# 側はスキャン対象外の指定などのヒントを出す。電源ドメインの記述と UPF 出力 | SX12c |

#### 位置づけ

- **Stage 6**（Stage 5 の後）。ただし **SX12f / SX12g（C# による検証基盤と既存 RTL の検証）は FPGA 側の Stage 4（HC8）と相性がよく、前倒しできる**。設計言語を乗り換えなくても使えるので、半導体の現場に入り込む入口になる
- 半導体の検証は商用 EDA と検証サービスの市場が大きく、FPGA 向けより利用の広がりが見込める
- ASIC 向けの機能は FPGA 向けの設計判断（2 値 Sim、初期値、ゲーテッドクロック除外）と衝突するので、**ターゲット種別で切り替える** 前提を HC2 / HC4 / HC6 の設計時から意識しておく

## 6. 進め方の規則

- マトリクスの行を **完了にするのは、方針ごとの完了条件（§1）を満たしたとき**。Emit だけ・Sim だけの対応は 🟡
- 新しい原語は Visitor 前提で足す（`IStmtVisitor` / `IExprVisitor<T>`）。追加漏れはコンパイルエラーで見つかる
- 1 Issue に詰め込みすぎない。HC1 なら「ビット演算とリダクション」「シフト」「乗除算」「Mux と繰り返し連結」のように分ける
- 到達度は Stage の終わりに再集計し、§1 の数字を更新する
