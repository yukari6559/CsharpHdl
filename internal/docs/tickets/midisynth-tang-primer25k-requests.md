## M1 — 制御: 比較 + `If` / `Else` — **完了**

**優先度:** 最高（UART / MIDI パーサ / ADSR / ボイス FSM の前提）  
**対応 L:** L1

| ID | 原語 | 完了の目安 | 状態 |
|----|------|------------|------|
| M1a | 比較（結果 1 bit）。C# では `==`/`!=` が衝突するため **`Eq`/`Neq` メソッド** + `< <= > >=` 演算子 | Comb / Seq の条件に使える | **完了**（`0.3.6`、`CompareComb` テスト） |
| M1b | `If` / `Else`。API は **名前付き** `If(cond, then: …, @else: …)`（`@else` 省略可）。ネスト可の方針を dsl-spec に固定 | 単純 FSM が Switch なしでも書ける | **完了**（`0.3.7`、Comb Emit/Sim + テスト） |
| M1c | `Switch` と条件分岐の役割分担を仕様に明記 | 消費者ドキュメントに「いつどっち」がある | **完了**（dsl-spec v0.3） |

**M1b API 方針（合意）:** 位置引数でも呼べるが、テスト・ドキュメントは名前付き前提。fluent `.Else` チェーンや `When` 三項は後回し可。

**消費者側で見ること:** ノートゲートやステート遷移が DSL フォークなしで書けること。

---

## M2 — 演算: 乗算・シフト・ビット論理 — **進行中**

**優先度:** 高（固定小数点音源の前提）  
**対応 L:** L1（GitHub: #9、HC1）

| ID | 原語 | 完了の目安 | 状態 |
|----|------|------------|------|
| M2a | 乗算 `*`（幅・切り捨て／拡張規則を仕様固定） | 波形 × エンベロープが 1 式で書ける | 未着手（#105 の幅の規則は済み） |
| M2b | 論理シフト `<<` / `>>`（少なくとも定数量。可変は方針決定） | Q フォーマット・分周・シリアル出しが書ける | 未着手（#105 の幅の規則は済み） |
| M2c | `^` / `~` | フラグ・簡易波形が `&`/`\|` だけで苦しまない | **一部完了**（`^` / `~^` は PR #103。`~` は #101） |

**完了の見方:** Core + Emit + Sim（S2 以降の解釈器）が同じ意味論。テストは小さな固定小数点スケール例で足りる（音色アルゴリズムは消費者）。

**先に直す正しさの問題:** #102（入れ子の演算の括弧。済み）、#105（演算の左右の幅。済み）、#104（式のスライス・符号拡張。済み）。どれも Sim と Verilog がずれうる問題だった。固定小数点の式は入れ子・幅違いが多いので、M2a / M2b より先に入れる。
